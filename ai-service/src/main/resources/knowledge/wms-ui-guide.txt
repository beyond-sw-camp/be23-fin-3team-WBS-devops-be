문서: WMS 화면 사용 가이드
목적: 신규 운영자가 메뉴를 찾지 못하거나 화면 사용 순서를 모를 때 챗봇이 화면 경로와 기본 조작 순서를 안내한다.
적용 대상: 시스템 운영자, 입고 담당자, 출고 담당자, 창고 관리자

영역: 입고 지시서 화면
화면 경로: 입고 관리 > 입고 지시서
사용 목적: 발주서 기반 입고 지시서를 조회하고 입고 예정, 검수, 적치 진행 상태를 확인한다.
주요 조작:
- 발주서 불러오기로 입고 지시서를 생성한다.
- 지시서번호 또는 입고처명으로 지시서를 검색한다.
- 상태 필터로 예정, 진행중, 완료 건을 구분한다.
- 상세 화면에서 품목별 주문 수량, 입고 수량, 불량 수량을 확인한다.
운영 안내:
- 상품이 도착하기 전에는 입고 예정 상태를 유지한다.
- 상품 도착 후 검수 결과를 확인한 뒤 적치 진행으로 넘긴다.
- 모든 품목의 정상 수량이 반영되고 예외가 없을 때 입고 완료 처리한다.

영역: 출고 지시서 화면
화면 경로: 출고 관리 > 출고 지시서
사용 목적: 출고 승인 건, 피킹 진행 건, 부분 출고 건을 조회하고 처리 우선순위를 확인한다.
주요 조작:
- 출고 지시서 번호, 매장, 창고, 상태로 검색한다.
- 승인 완료 건은 피킹 리스트 생성 전 상태로 본다.
- 피킹 진행 건은 작업자 배정 및 피킹 수량을 확인한다.
- 부분 출고 건은 미출고 잔여 수량과 사유를 확인한다.
운영 안내:
- 오늘 출고 예정인 승인 완료 건은 먼저 피킹 가능 여부를 확인한다.
- 피킹 진행 중인 건은 피킹 완료율과 재고 예약 상태를 함께 확인한다.

영역: 피킹 리스트 화면
화면 경로: 지시서 목록 > 피킹 리스트
사용 목적: 작업자에게 배정된 피킹 작업과 품목별 피킹 진행 상태를 확인한다.
주요 조작:
- 피킹리스트 번호로 작업 상세를 조회한다.
- 대기, 진행 중, 완료 상태로 작업 목록을 구분한다.
- 품목별 목표 수량과 실제 피킹 수량을 확인한다.
- 피킹 완료 전 로케이션 코드와 상품 코드를 대조한다.
운영 안내:
- 작업자가 "내 피킹 작업"을 묻는 경우 이 화면의 배정 작업 기준으로 안내한다.
- 피킹 수량이 목표 수량보다 적으면 부분 피킹 또는 재고 부족 여부를 확인한다.

영역: 재고 조회 화면
화면 경로: 재고 관리 > 재고 조회
사용 목적: 상품별 가용 재고, 예약 재고, 입고 예정 재고, 불량 재고와 보관 위치를 확인한다.
주요 조작:
- 상품명, SKU, 창고, 구역, 랙, 로케이션으로 검색한다.
- 가용 수량은 즉시 출고 가능한 수량이다.
- 예약 수량은 이미 출고 지시서에 묶인 수량이다.
- 입고 예정 수량은 아직 정상 재고로 전환되지 않은 수량이다.
운영 안내:
- "상품 어디 있어?" 질문은 재고 조회 화면의 창고, 구역, 랙, 로케이션 정보를 기준으로 답한다.
- 예약 수량이 많으면 실제 가용 재고가 부족할 수 있으므로 가용 수량을 우선 확인한다.

영역: 로케이션 및 랙 관리 화면
화면 경로: 창고 관리 > 레이아웃 편집 또는 창고 관리 > 랙/로케이션 관리
사용 목적: 창고의 구역, 랙, 로케이션 구조와 활성 여부를 관리한다.
주요 조작:
- 창고별 구역을 확인한다.
- 구역 안의 랙과 층별 로케이션을 확인한다.
- 비활성 로케이션은 신규 적치 후보에서 제외한다.
- 랙 수용량과 현재 사용량을 확인한다.
운영 안내:
- 로케이션이 미지정된 입고 품목은 적치 후보를 먼저 배정해야 한다.
- 같은 SKU가 이미 보관된 로케이션이 있으면 병합 적치를 우선 검토한다.

영역: 관리자 작업 실패 원인 안내
화면 경로: 공통 > 알림 또는 작업을 시도한 원래 화면
사용 목적: 관리자가 웹서비스에서 생성, 승인, 완료, 배정 작업을 시도했을 때 실패 원인을 빠르게 좁힌다.
주요 조작:
- 화면 상단 토스트, 모달, 오류 메시지의 문구를 먼저 확인한다.
- 같은 조건으로 재시도하기 전에 검색 조건, 선택한 창고, 상품, 수량, 상태값을 확인한다.
- 실패한 작업의 대상 번호를 확인한다. 예: 입고 지시서 번호, 출고 지시서 번호, 피킹 리스트 번호, 적치 지시서 번호.
- 권한이 필요한 메뉴라면 로그인 사용자 역할과 권한을 확인한다.
운영 안내:
- 챗봇에 실패 원인을 물을 때는 "어느 화면에서", "무슨 버튼을 눌렀는지", "어떤 메시지가 떴는지"를 함께 말하면 원인 후보를 좁힐 수 있다.
- 같은 작업을 반복 실행하면 중복 생성 또는 상태 충돌이 생길 수 있으므로, 목록 화면에서 대상 상태가 바뀌었는지 먼저 새로고침한다.
- 실패 원인은 대부분 상태 불일치, 필수 값 누락, 가용 재고 부족, 비활성 마스터 데이터, 권한 부족, 이미 처리된 문서 중 하나다.

영역: 출고 지시서 생성 실패
화면 경로: 출고 관리 > 출고 지시서
사용 목적: 관리자가 출고 지시서를 생성하거나 승인할 때 실패한 이유를 확인한다.
주요 조작:
- 상품이 활성 상태인지 확인한다.
- 출고 창고가 선택되어 있고 해당 창고에 상품 재고가 있는지 확인한다.
- 재고 조회 화면에서 가용 수량과 예약 수량을 확인한다.
- 매장, 거래처, 배송지 등 출고처 정보가 누락되지 않았는지 확인한다.
- 이미 같은 판매 주문 또는 반품 출고 건으로 출고 지시서가 생성되었는지 확인한다.
운영 안내:
- 가용 수량이 부족하면 출고 지시서 생성 또는 승인이 실패할 수 있다.
- 예약 수량이 많으면 총 재고가 있어도 신규 출고에 사용할 수 없다.
- 승인 완료 이후에는 같은 지시서를 다시 승인하지 말고 피킹 리스트 생성 단계로 이동한다.
- 부분 출고가 필요한 경우에는 부족 품목을 확인한 뒤 지시서 분할 또는 수량 조정을 검토한다.

영역: 피킹 리스트 생성 실패
화면 경로: 출고 관리 > 피킹 리스트
사용 목적: 승인된 출고 지시서에서 피킹 리스트 생성이 실패한 이유를 확인한다.
주요 조작:
- 출고 지시서 상태가 승인 완료인지 확인한다.
- 출고 품목별 예약 재고가 존재하는지 확인한다.
- 작업자 자동 배정이 필요한 경우 활성 작업자와 담당 가능 창고를 확인한다.
- 피킹할 로케이션이 비활성 상태인지 확인한다.
- 이미 피킹 리스트가 생성된 출고 지시서인지 확인한다.
운영 안내:
- 승인 전 지시서는 피킹 리스트를 생성할 수 없다.
- 예약 재고가 없거나 로케이션이 비활성화되어 있으면 피킹 작업을 만들 수 없다.
- 작업자 배정 실패가 발생하면 작업자 계정 상태, 권한, 마지막 작업 위치 정보를 확인한다.

영역: 입고 검수 및 적치 실패
화면 경로: 입고 관리 > 입고 검수 또는 입고 관리 > 적치 지시서
사용 목적: 입고 수량 반영, 불량 등록, 적치 완료가 실패한 이유를 확인한다.
주요 조작:
- 입고 지시서 상태가 검수 또는 적치 가능한 단계인지 확인한다.
- 검수 수량이 주문 수량을 초과하지 않았는지 확인한다.
- 불량 수량을 입력한 경우 불량 사유와 증빙 파일이 필요한지 확인한다.
- 적치 대상 로케이션의 수용 가능 수량과 활성 여부를 확인한다.
- 불량 상품은 불량 구역 또는 반품/불량 목적 창고 정책에 맞는 위치인지 확인한다.
운영 안내:
- 이미 완료된 입고 지시서는 다시 검수하거나 적치 완료할 수 없다.
- 정상 수량과 불량 수량의 합계가 주문 또는 입고 대상 수량과 맞지 않으면 완료 처리가 실패할 수 있다.
- 로케이션 수용량을 초과하면 적치 완료가 실패한다.
- 상품 보관 규칙과 맞지 않는 구역을 선택하면 추천 위치가 나오지 않거나 적치가 제한될 수 있다.

영역: 불량 증빙 사진 확인
화면 경로: 문서/증빙 관리 > 불량 증빙 또는 입고 관리 > 입고 검수 상세의 불량 품목 영역
사용 목적: 불량 처리 시 업로드한 사진, 첨부 파일, 사유, 업로드 상태를 확인한다.
주요 조작:
- 불량이 발생한 원천 문서 번호 또는 품목명으로 검색한다.
- 상태 필터에서 대기, 준비 완료, 고아 파일 상태를 구분한다.
- 불량 증빙 목록에서 파일명, MIME 타입, 업로드 시각, 업로드 담당자를 확인한다.
- 상세 화면에서 다운로드 또는 미리보기 버튼으로 증빙 사진을 확인한다.
- 입고 검수 상세에서는 불량 수량이 있는 품목을 먼저 펼친 뒤 연결된 증빙 파일을 확인한다.
운영 안내:
- 사용자가 "불량 사진 어디서 봐?", "불량 증빙 어디 있어?", "증빙 파일 어디서 확인해?"라고 물으면 이 화면 경로를 안내한다.
- 사진이 보이지 않으면 불량 수량이 실제로 등록되었는지, 증빙 파일 상태가 READY인지, 업로드가 완료되었는지 확인한다.
- 업로드 직후 목록에 보이지 않으면 새로고침하거나 원천 문서 번호로 다시 검색한다.
- 증빙 파일은 불량 처리 근거이므로 삭제 전 담당자와 상태를 확인한다.

영역: 재고 조정 및 재고 실사 실패
화면 경로: 재고 관리 > 재고 조정 또는 재고 관리 > 재고 실사
사용 목적: 관리자가 재고 조정, 실사 생성, 실사 완료를 시도했을 때 실패 원인을 확인한다.
주요 조작:
- 조정 대상 상품, 창고, 로케이션이 모두 선택되었는지 확인한다.
- 차감 조정 시 가용 수량이 충분한지 확인한다.
- 실사 대상 로케이션이 이미 다른 진행 중 실사에 포함되어 있는지 확인한다.
- 실사 수량 입력값이 음수이거나 비어 있지 않은지 확인한다.
- 실사 완료 전에 모든 실사 품목이 입력 완료 상태인지 확인한다.
운영 안내:
- 예약 수량은 이미 출고 작업에 묶여 있으므로 임의 차감 대상이 아니다.
- 진행 중 실사가 있는 로케이션은 중복 실사를 생성하지 않는다.
- 실사 완료 후에는 재고 스냅샷과 재고 트랜잭션이 함께 반영되는지 확인한다.

영역: 마스터 데이터 저장 실패
화면 경로: 기준 정보 관리 > 상품, 창고, 구역, 랙, 로케이션, 공급사, 매장
사용 목적: 관리자가 기준 정보를 생성 또는 수정할 때 실패한 이유를 확인한다.
주요 조작:
- 필수 입력값이 비어 있지 않은지 확인한다.
- 코드, SKU, 바코드처럼 중복이 제한된 값이 이미 존재하는지 확인한다.
- 상위 카테고리, 창고, 구역, 랙 같은 참조 대상이 활성 상태인지 확인한다.
- 창고 타입과 구역 타입이 업무 목적에 맞는지 확인한다.
- 삭제 또는 비활성화하려는 데이터가 진행 중인 입고, 출고, 재고에 연결되어 있는지 확인한다.
운영 안내:
- 이미 재고가 있거나 진행 중 작업에 연결된 마스터 데이터는 삭제보다 비활성 처리를 우선 검토한다.
- 상품 코드와 SKU는 다른 상품과 중복되면 저장이 실패할 수 있다.
- 창고, 구역, 랙, 로케이션 구조가 맞지 않으면 적치 추천과 피킹 작업 생성에도 영향을 준다.

영역: 알림 및 웹소켓 수신 실패
화면 경로: 알림 센터 또는 대시보드
사용 목적: 관리자가 부족 재고, 출고 부족, 작업 배정 알림을 받지 못했을 때 원인을 확인한다.
주요 조작:
- 로그인 사용자가 해당 회사 또는 창고의 알림 대상인지 확인한다.
- 브라우저가 웹소켓 연결을 유지 중인지 새로고침 후 확인한다.
- 알림 조건이 실제로 발생했는지 부족 재고, 출고 부족, 작업 배정 화면에서 확인한다.
- 같은 회사의 다른 관리자 계정에서도 알림이 보이는지 확인한다.
운영 안내:
- 알림은 권한, 회사, 창고 범위에 따라 필터링될 수 있다.
- 웹소켓 연결이 끊겼다면 새로고침 또는 재로그인 후 다시 확인한다.
- 알림이 생성되지 않았다면 스케줄러 실행 여부와 관련 작업 상태를 함께 확인한다.
