문서: WMS 화면 사용 가이드
목적: 신규 운영자가 메뉴를 찾지 못하거나 화면 사용 순서를 모를 때 챗봇이 화면 경로와 기본 조작 순서를 안내한다.
적용 대상: 시스템 운영자, 입고 담당자, 출고 담당자, 창고 관리자

영역: 입고 지시서 화면
화면 경로: 입고 관리 > 입고 지시서
사용 목적: 발주서 기반 입고 지시서를 조회하고 입고 예정, 검수, 적치 진행 상태를 확인한다.
주요 조작:
- 발주서 불러오기로 입고 지시서를 생성한다.
- 지시서번호 또는 입고처명으로 지시서를 검색한다.
- 상태 필터로 예정, 진행중, 완료 건을 구분한다.
- 상세 화면에서 품목별 주문 수량, 입고 수량, 불량 수량을 확인한다.
운영 안내:
- 상품이 도착하기 전에는 입고 예정 상태를 유지한다.
- 상품 도착 후 검수 결과를 확인한 뒤 적치 진행으로 넘긴다.
- 모든 품목의 정상 수량이 반영되고 예외가 없을 때 입고 완료 처리한다.

영역: 출고 지시서 화면
화면 경로: 출고 관리 > 출고 지시서
사용 목적: 출고 승인 건, 피킹 진행 건, 부분 출고 건을 조회하고 처리 우선순위를 확인한다.
주요 조작:
- 출고 지시서 번호, 매장, 창고, 상태로 검색한다.
- 승인 완료 건은 피킹 리스트 생성 전 상태로 본다.
- 피킹 진행 건은 피킹 상태와 품목별 수량을 확인한다.
- 부분 출고 건은 미출고 잔여 수량과 사유를 확인한다.
운영 안내:
- 오늘 출고 예정인 승인 완료 건은 먼저 피킹 가능 여부를 확인한다.
- 피킹 진행 중인 건은 피킹 완료율과 재고 예약 상태를 함께 확인한다.

영역: 피킹 리스트 화면
화면 경로: 지시서 목록 > 피킹 리스트
사용 목적: 피킹 작업과 품목별 피킹 진행 상태를 확인한다.
주요 조작:
- 피킹리스트 번호로 작업 상세를 조회한다.
- 대기, 진행 중, 완료 상태로 작업 목록을 구분한다.
- 품목별 목표 수량과 실제 피킹 수량을 확인한다.
- 피킹 완료 전 로케이션 코드와 상품 코드를 대조한다.
운영 안내:
- 피킹 수량이 목표 수량보다 적으면 부분 피킹 또는 재고 부족 여부를 확인한다.

영역: 재고 조회 화면
화면 경로: 재고 관리 > 재고 조회
사용 목적: 상품별 가용 재고, 예약 재고, 입고 예정 재고, 불량 재고와 보관 위치를 확인한다.
주요 조작:
- 상품명, SKU, 창고, 구역, 랙, 로케이션으로 검색한다.
- 가용 수량은 즉시 출고 가능한 수량이다.
- 예약 수량은 이미 출고 지시서에 묶인 수량이다.
- 입고 예정 수량은 아직 정상 재고로 전환되지 않은 수량이다.
운영 안내:
- "상품 어디 있어?" 질문은 재고 조회 화면의 창고, 구역, 랙, 로케이션 정보를 기준으로 답한다.
- 예약 수량이 많으면 실제 가용 재고가 부족할 수 있으므로 가용 수량을 우선 확인한다.

영역: 로케이션 및 랙 관리 화면
화면 경로: 창고 관리 > 레이아웃 편집 또는 창고 관리 > 랙/로케이션 관리
사용 목적: 창고의 구역, 랙, 로케이션 구조와 활성 여부를 관리한다.
주요 조작:
- 창고별 구역을 확인한다.
- 구역 안의 랙과 층별 로케이션을 확인한다.
- 비활성 로케이션은 신규 적치 후보에서 제외한다.
- 랙 수용량과 현재 사용량을 확인한다.
운영 안내:
- 로케이션이 미지정된 입고 품목은 적치 후보를 먼저 배정해야 한다.
- 같은 SKU가 이미 보관된 로케이션이 있으면 병합 적치를 우선 검토한다.

영역: 관리자 작업 실패 원인 안내
화면 경로: 공통 > 알림 또는 작업을 시도한 원래 화면
사용 목적: 관리자가 웹서비스에서 생성, 승인, 완료 작업을 시도했을 때 실패 원인을 빠르게 좁힌다.
주요 조작:
- 화면 상단 토스트, 모달, 오류 메시지의 문구를 먼저 확인한다.
- 같은 조건으로 재시도하기 전에 검색 조건, 선택한 창고, 상품, 수량, 상태값을 확인한다.
- 실패한 작업의 대상 번호를 확인한다. 예: 입고 지시서 번호, 출고 지시서 번호, 피킹 리스트 번호, 적치 지시서 번호.
- 권한이 필요한 메뉴라면 로그인 사용자 역할과 권한을 확인한다.
운영 안내:
- 챗봇에 실패 원인을 물을 때는 "어느 화면에서", "무슨 버튼을 눌렀는지", "어떤 메시지가 떴는지"를 함께 말하면 원인 후보를 좁힐 수 있다.
- 같은 작업을 반복 요청하면 중복 생성 또는 상태 충돌이 생길 수 있으므로, 목록 화면에서 대상 상태가 바뀌었는지 먼저 새로고침한다.
- 실패 원인은 대부분 상태 불일치, 필수 값 누락, 가용 재고 부족, 비활성 마스터 데이터, 권한 부족, 이미 처리된 문서 중 하나다.

영역: 출고 지시서 생성 실패
화면 경로: 출고 관리 > 출고 지시서
사용 목적: 관리자가 출고 지시서를 생성하거나 승인할 때 실패한 이유를 확인한다.
주요 조작:
- 상품이 활성 상태인지 확인한다.
- 출고 창고가 선택되어 있고 해당 창고에 상품 재고가 있는지 확인한다.
- 재고 조회 화면에서 가용 수량과 예약 수량을 확인한다.
- 매장, 거래처, 배송지 등 출고처 정보가 누락되지 않았는지 확인한다.
- 이미 같은 판매 주문 또는 반품 출고 건으로 출고 지시서가 생성되었는지 확인한다.
운영 안내:
- 가용 수량이 부족하면 출고 지시서 생성 또는 승인이 실패할 수 있다.
- 예약 수량이 많으면 총 재고가 있어도 신규 출고에 사용할 수 없다.
- 승인 완료 이후에는 같은 지시서를 다시 승인하지 말고 피킹 리스트 생성 단계로 이동한다.
- 부분 출고가 필요한 경우에는 부족 품목을 확인한 뒤 지시서 분할 또는 수량 조정을 검토한다.

영역: 피킹 리스트 생성 실패
화면 경로: 출고 관리 > 피킹 리스트
사용 목적: 승인된 출고 지시서에서 피킹 리스트 생성이 실패한 이유를 확인한다.
주요 조작:
- 출고 지시서 상태가 승인 완료인지 확인한다.
- 출고 품목별 예약 재고가 존재하는지 확인한다.
- 피킹할 로케이션이 비활성 상태인지 확인한다.
- 이미 피킹 리스트가 생성된 출고 지시서인지 확인한다.
운영 안내:
- 승인 전 지시서는 피킹 리스트를 생성할 수 없다.
- 예약 재고가 없거나 로케이션이 비활성화되어 있으면 피킹 작업을 만들 수 없다.
- 피킹 대상 재고나 로케이션 조건이 맞지 않으면 피킹 리스트 생성이 실패할 수 있다.

영역: 입고 검수 및 적치 실패
화면 경로: 입고 관리 > 입고 검수 또는 입고 관리 > 적치 지시서
사용 목적: 입고 수량 반영, 불량 등록, 적치 완료가 실패한 이유를 확인한다.
주요 조작:
- 입고 지시서 상태가 검수 또는 적치 가능한 단계인지 확인한다.
- 검수 수량이 주문 수량을 초과하지 않았는지 확인한다.
- 불량 수량을 입력한 경우 불량 사유와 증빙 파일이 필요한지 확인한다.
- 적치 대상 로케이션의 수용 가능 수량과 활성 여부를 확인한다.
- 불량 상품은 불량 구역 또는 반품/불량 목적 창고 정책에 맞는 위치인지 확인한다.
운영 안내:
- 이미 완료된 입고 지시서는 다시 검수하거나 적치 완료할 수 없다.
- 정상 수량과 불량 수량의 합계가 주문 또는 입고 대상 수량과 맞지 않으면 완료 처리가 실패할 수 있다.
- 로케이션 수용량을 초과하면 적치 완료가 실패한다.
- 상품 보관 규칙과 맞지 않는 구역을 선택하면 추천 위치가 나오지 않거나 적치가 제한될 수 있다.

영역: 불량 증빙 사진 확인
화면 경로: 문서/증빙 관리 > 불량 증빙 또는 입고 관리 > 입고 검수 상세의 불량 품목 영역
사용 목적: 불량 처리 시 업로드한 사진, 첨부 파일, 사유, 업로드 상태를 확인한다.
주요 조작:
- 불량이 발생한 원천 문서 번호 또는 품목명으로 검색한다.
- 상태 필터에서 대기, 준비 완료, 고아 파일 상태를 구분한다.
- 불량 증빙 목록에서 파일명, MIME 타입, 업로드 시각, 업로드 담당자를 확인한다.
- 상세 화면에서 다운로드 또는 미리보기 버튼으로 증빙 사진을 확인한다.
- 입고 검수 상세에서는 불량 수량이 있는 품목을 먼저 펼친 뒤 연결된 증빙 파일을 확인한다.
운영 안내:
- 사용자가 "불량 사진 어디서 봐?", "불량 증빙 어디 있어?", "증빙 파일 어디서 확인해?"라고 물으면 이 화면 경로를 안내한다.
- 사진이 보이지 않으면 불량 수량이 실제로 등록되었는지, 증빙 파일 상태가 READY인지, 업로드가 완료되었는지 확인한다.
- 업로드 직후 목록에 보이지 않으면 새로고침하거나 원천 문서 번호로 다시 검색한다.
- 증빙 파일은 불량 처리 근거이므로 삭제 전 담당자와 상태를 확인한다.

영역: 재고 조정 및 재고 실사 실패
화면 경로: 재고 관리 > 재고 조정 또는 재고 관리 > 재고 실사
사용 목적: 관리자가 재고 조정, 실사 생성, 실사 완료를 시도했을 때 실패 원인을 확인한다.
주요 조작:
- 조정 대상 상품, 창고, 로케이션이 모두 선택되었는지 확인한다.
- 차감 조정 시 가용 수량이 충분한지 확인한다.
- 실사 대상 로케이션이 이미 다른 진행 중 실사에 포함되어 있는지 확인한다.
- 실사 수량 입력값이 음수이거나 비어 있지 않은지 확인한다.
- 실사 완료 전에 모든 실사 품목이 입력 완료 상태인지 확인한다.
운영 안내:
- 예약 수량은 이미 출고 작업에 묶여 있으므로 임의 차감 대상이 아니다.
- 진행 중 실사가 있는 로케이션은 중복 실사를 생성하지 않는다.
- 실사 완료 후에는 재고 스냅샷과 재고 트랜잭션이 함께 반영되는지 확인한다.

영역: 마스터 데이터 저장 실패
화면 경로: 기준 정보 관리 > 상품, 창고, 구역, 랙, 로케이션, 공급사, 매장
사용 목적: 관리자가 기준 정보를 생성 또는 수정할 때 실패한 이유를 확인한다.
주요 조작:
- 필수 입력값이 비어 있지 않은지 확인한다.
- 코드, SKU, 바코드처럼 중복이 제한된 값이 이미 존재하는지 확인한다.
- 상위 카테고리, 창고, 구역, 랙 같은 참조 대상이 활성 상태인지 확인한다.
- 창고 타입과 구역 타입이 업무 목적에 맞는지 확인한다.
- 삭제 또는 비활성화하려는 데이터가 진행 중인 입고, 출고, 재고에 연결되어 있는지 확인한다.
운영 안내:
- 이미 재고가 있거나 진행 중 작업에 연결된 마스터 데이터는 삭제보다 비활성 처리를 우선 검토한다.
- 상품 코드와 SKU는 다른 상품과 중복되면 저장이 실패할 수 있다.
- 창고, 구역, 랙, 로케이션 구조가 맞지 않으면 적치 추천과 피킹 작업 생성에도 영향을 준다.

영역: 알림 및 웹소켓 수신 실패
화면 경로: 알림 센터 또는 대시보드
사용 목적: 관리자가 부족 재고, 출고 부족, 업무 알림을 받지 못했을 때 원인을 확인한다.
주요 조작:
- 로그인 사용자가 해당 회사 또는 창고의 알림 대상인지 확인한다.
- 브라우저가 웹소켓 연결을 유지 중인지 새로고침 후 확인한다.
- 알림 조건이 실제로 발생했는지 부족 재고, 출고 부족, 관련 업무 화면에서 확인한다.
- 같은 회사의 다른 관리자 계정에서도 알림이 보이는지 확인한다.
운영 안내:
- 알림은 권한, 회사, 창고 범위에 따라 필터링될 수 있다.
- 웹소켓 연결이 끊겼다면 새로고침 또는 재로그인 후 다시 확인한다.
- 알림이 생성되지 않았다면 스케줄러 상태와 관련 작업 상태를 함께 확인한다.

영역: 세션 시간 연장 및 로그아웃
화면 경로: 상단 헤더의 남은 시간 표시 또는 우측 상단 사용자 메뉴
사용 목적: 관리자가 로그인 세션을 유지하거나 안전하게 로그아웃한다.
주요 조작:
- 상단 헤더의 남은 시간 표시를 확인한다.
- 세션 만료가 가까워지면 현재 작업을 저장한 뒤 화면을 새로고침하거나 다시 로그인한다.
- 우측 상단 사용자 아이콘 또는 사용자 메뉴에서 로그아웃을 선택한다.
- 공용 PC나 공유 브라우저에서는 작업 완료 후 반드시 로그아웃한다.
운영 안내:
- 세션 시간 연장 기능이 별도 버튼으로 제공되지 않는 환경에서는 저장되지 않은 입력값을 먼저 저장하고 재로그인한다.
- 로그아웃 후에는 브라우저 뒤로가기로 이전 업무 화면에 접근할 수 없는지 확인한다.
- 세션 만료로 작업이 중단되면 다시 로그인한 뒤 대상 지시서의 최신 상태를 먼저 조회한다.

영역: 번호 생성 기준
화면 경로: 공통 관리 > 공통 코드 또는 각 지시서 생성 화면
사용 목적: 지시서 번호와 업무 번호가 어떤 기준으로 생성되는지 이해한다.
주요 조작:
- 입고 지시서 번호는 IB, 출고 지시서 번호는 OB, 적치 지시서 번호는 PO, 이동 지시서 번호는 TR, 피킹 리스트 번호는 PL 같은 업무 prefix를 사용한다.
- 번호에는 생성일 또는 업무 기준일을 나타내는 날짜와 일련번호가 포함된다.
- 번호는 시스템이 자동으로 생성하므로 운영자가 임의로 수정하지 않는다.
- 중복 번호가 보이면 새로고침 후 목록을 다시 조회하고, 같은 요청이 반복되었는지 확인한다.
운영 안내:
- 번호 생성 기준은 업무 유형을 빠르게 구분하기 위한 식별 규칙이다.
- 번호가 생성되지 않으면 필수 기준 정보, 문서 상태, 중복 요청 여부를 먼저 확인한다.
- 공통 코드 관리는 업무 코드와 표시명을 관리하는 영역이며, 지시서 번호 자체를 수동 채번하는 화면이 아니다.

영역: 오류 코드 및 실패 메시지 확인
화면 경로: 공통 관리 > 알림, 공통 관리 > 감사 로그 또는 작업을 시도한 원래 화면
사용 목적: 관리자가 오류 코드, 실패 메시지, 작업 실패 이력을 확인한다.
주요 조작:
- 화면 상단 토스트나 모달에 표시된 오류 메시지를 먼저 확인한다.
- 반복 실패하는 작업은 공통 관리 > 감사 로그에서 요청 시간, 사용자, URI, 응답 상태를 확인한다.
- 오류 코드가 표시되면 코드값만 보지 말고 어떤 업무 번호에서 실패했는지 함께 확인한다.
- 권한 오류는 사용자 역할과 메뉴 권한을 확인한다.
- 상태 오류는 대상 지시서가 이미 승인, 진행, 완료, 취소 상태인지 확인한다.
운영 안내:
- 오류 코드 관리는 단순 코드 목록보다 실제 실패 화면과 감사 로그를 함께 보는 방식으로 확인한다.
- 사용자에게 보여줄 답변은 내부 예외명이나 stack trace가 아니라 조치 가능한 원인 후보와 확인 화면을 안내한다.
- 원인을 좁히기 어려우면 실패한 업무 번호, 버튼명, 오류 메시지를 함께 기록한다.

영역: WMS 오류 코드 기준 및 조치 가이드
화면 경로: 오류가 발생한 원래 화면, 공통 관리 > 감사 로그, 공통 관리 > 알림
사용 목적: 관리자가 지시서 생성, 검수 완료, 피킹 리스트 생성, 파일 업로드 실패 원인을 빠르게 분류하고 조치한다.
오류 코드 체계:
- AUTH-403: 권한 또는 역할 부족. 메뉴 접근, 버튼 조작, 조회 범위가 사용자 역할에 허용되지 않을 때 발생한다.
- AUTH-401: 로그인 세션 만료 또는 인증 실패. 장시간 미사용 후 요청하거나 토큰이 만료되었을 때 발생한다.
- MENU-404: 메뉴 또는 화면 접근 불가. 권한, 라우팅 경로, 배포 버전 불일치로 메뉴가 보이지 않을 때 확인한다.
- FILE-400: 파일 형식 또는 용량 오류. 허용 확장자, MIME 타입, 파일 크기 제한을 확인한다.
- FILE-500: 파일 저장소 업로드 실패. 네트워크, S3 또는 파일 저장 설정을 확인한다.
- DOC-400: 지시서 생성 조건 부족. 필수 입력값, 거래처, 창고, 상품, 수량, 예정일이 누락되었는지 확인한다.
- DOC-409: 지시서 상태 충돌. 이미 승인, 진행, 완료, 취소된 문서를 다시 생성하거나 수정하려고 할 때 발생한다.
- INB-409: 입고 검수 완료 불가. 검수 수량 불일치, 불량 증빙 누락, 이미 완료된 입고 지시서 상태를 확인한다.
- OUT-409: 출고 지시서 생성 실패. 가용 재고 부족, 출고 예정일 오류, 고객/배송 정보 누락, 출고 가능 상태를 확인한다.
- PICK-409: 피킹 리스트 생성 실패. 출고 지시서 상태, 피킹 대상 재고, 로케이션 조건을 확인한다.
- INV-409: 재고 수량 불일치. 보류 재고, 할당 재고, 이동 중 재고, 최근 입출고 반영 여부를 확인한다.
- CODE-409: 공통 코드 중복 또는 사용 중인 코드 수정 불가. 이미 사용 중인 코드인지, 삭제 대신 비활성화가 필요한지 확인한다.
- MASTER-409: 마스터 데이터 비활성화 불가. 창고, 로케이션, 상품이 진행 중 작업이나 재고에 연결되어 있는지 확인한다.
운영 안내:
- 오류 코드는 사용자에게 문제 유형을 짧게 알려주고, 실제 조치는 원래 화면의 메시지와 감사 로그를 함께 확인한다.
- 답변은 코드명, 가능한 원인, 확인 화면, 우선 조치 순서로 제공한다.
- 내부 예외명, DB stack trace, 시스템 토큰, 개인정보는 사용자 답변에 포함하지 않는다.

영역: 권한 오류 및 메뉴 미노출
화면 경로: 공통 관리 > 사용자 관리, 공통 관리 > 역할/권한 관리, 접근하려는 업무 메뉴
사용 목적: 권한 없다고 표시되거나 메뉴가 보이지 않는 상황을 해결한다.
주요 조작:
- 로그인한 사용자의 역할과 회사, 창고 접근 범위를 확인한다.
- 해당 메뉴의 조회, 생성, 수정, 삭제 권한이 역할에 포함되어 있는지 확인한다.
- 관리자 계정으로는 보이지만 일반 계정에서 보이지 않으면 역할 권한 차이로 판단한다.
- 권한 변경 후에도 메뉴가 보이지 않으면 로그아웃 후 다시 로그인한다.
운영 안내:
- 권한 오류는 AUTH-403으로 분류한다.
- 메뉴 미노출은 권한 문제, 배포 버전 불일치, 브라우저 캐시 문제 순서로 확인한다.

영역: 파일 업로드 및 불량 증빙 사진 확인
화면 경로: 문서/증빙 관리 > 작업 증빙, 반품 관리 > 불량 처리, 입고/출고 검수 상세 화면
사용 목적: 불량 사진, 검수 증빙, 첨부 파일 등록 및 조회 실패를 확인한다.
주요 조작:
- 작업 증빙 화면에서 증빙 유형을 선택해 등록된 파일을 조회한다.
- 불량 증빙은 불량 처리 또는 검수 상세 화면의 증빙 영역에서 확인한다.
- 업로드 실패 시 파일 확장자, 용량, 네트워크 상태를 먼저 확인한다.
- 같은 파일을 반복 업로드하기보다 파일명을 바꾸거나 용량을 줄인 뒤 다시 시도한다.
운영 안내:
- 파일 형식이나 용량 문제는 FILE-400으로 분류한다.
- 저장소 또는 네트워크 문제는 FILE-500으로 분류한다.
- 불량 증빙이 보이지 않으면 업무 번호, 증빙 유형, 등록자, 등록 시각을 함께 확인한다.

영역: 지시서 생성 및 처리 실패
화면 경로: 입고 관리 > 입고 지시서, 출고 관리 > 출고 지시서, 지시서 목록 > 전체 지시서 목록
사용 목적: 입고 검수 완료, 출고 지시서 생성, 피킹 리스트 생성이 실패한 원인을 확인한다.
주요 조작:
- 입고 검수 완료 실패 시 검수 수량, 불량 수량, 증빙 첨부 여부, 지시서 상태를 확인한다.
- 출고 지시서 생성 실패 시 가용 재고, 주문 상태, 출고 예정일, 고객/배송 정보를 확인한다.
- 피킹 리스트 생성 실패 시 출고 지시서가 승인 또는 피킹 가능 상태인지 확인한다.
- 동일 업무 번호로 중복 생성 요청을 보내지 않았는지 확인한다.
운영 안내:
- 필수값 부족은 DOC-400으로 분류한다.
- 이미 처리된 문서나 상태 충돌은 DOC-409로 분류한다.
- 입고 처리 실패는 INB-409, 출고 생성 실패는 OUT-409, 피킹 생성 실패는 PICK-409로 분류한다.

영역: 재고 수량 차이 및 재고 반영 지연
화면 경로: 재고 관리 > 재고 조회, 창고 모니터링, 입고/출고/이동 상세 화면
사용 목적: 화면마다 재고 수량이 다르거나 예상 수량과 맞지 않을 때 원인을 확인한다.
주요 조작:
- 가용 재고, 보류 재고, 할당 재고, 이동 중 재고를 구분해서 확인한다.
- 최근 입고, 출고, 이동, 실사 조정이 반영되었는지 확인한다.
- 창고 또는 로케이션 필터가 서로 다른지 확인한다.
- 재고 부족 품목은 출고 예약 또는 피킹 할당으로 가용 수량이 줄었는지 확인한다.
운영 안내:
- 재고 수량 차이는 INV-409로 분류한다.
- 총 재고와 가용 재고는 다를 수 있으며, 출고 예약과 피킹 할당이 있으면 가용 재고가 줄어든다.

영역: 엑셀 다운로드 및 QR/바코드 재출력
화면 경로: 각 목록 화면의 다운로드 버튼, 입고/출고/재고 상세 화면의 QR 또는 바코드 출력 버튼
사용 목적: 목록 데이터를 내려받거나 업무 번호, 상품, 로케이션 식별 코드를 다시 출력한다.
주요 조작:
- 목록 화면에서 검색 조건을 먼저 적용한 뒤 엑셀 다운로드를 요청한다.
- 다운로드가 되지 않으면 브라우저 팝업 차단과 다운로드 권한을 확인한다.
- QR 또는 바코드는 대상 업무 번호, 상품, 로케이션 상세 화면에서 재출력한다.
- 출력 내용이 다르면 최신 상태로 새로고침 후 다시 출력한다.
운영 안내:
- 다운로드 권한이 없으면 AUTH-403으로 분류한다.
- QR 또는 바코드가 없는 데이터는 먼저 대상 코드가 정상 생성되었는지 확인한다.

영역: 공통 코드 수정 영향 및 마스터 비활성화
화면 경로: 공통 관리 > 공통 코드, 마스터 관리 > 창고/구역/랙/로케이션/상품
사용 목적: 공통 코드나 마스터 데이터를 수정, 삭제, 비활성화할 때 업무 영향 범위를 확인한다.
주요 조작:
- 공통 코드는 화면 표시명, 상태값, 업무 분류, 검색 조건에 영향을 줄 수 있다.
- 운영 중인 코드는 삭제보다 비활성화를 우선 검토한다.
- 창고나 로케이션 비활성화 전 진행 중 작업, 보유 재고, 할당 재고가 있는지 확인한다.
- 코드 변경 후에는 관련 화면의 검색 조건과 표시명이 바뀌는지 확인한다.
운영 안내:
- 공통 코드 중복이나 사용 중 수정 불가는 CODE-409로 분류한다.
- 창고, 로케이션, 상품 비활성화 실패는 MASTER-409로 분류한다.
- 진행 중 작업이나 재고가 연결된 마스터 데이터는 즉시 비활성화되지 않을 수 있다.
