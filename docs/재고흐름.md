# WMS 재고 흐름 전체 맵

## 1. 일반 입고

```
[발주서/수동]  →  [입고지시서]  →  [승인]  →  [검수]  →  [적치]  →  [완료]
```

### 재고 변동

| 단계 | 변화 | 위치 |
|------|------|------|
| 승인 | incoming ↑ | null |
| 검수 (정상) | incoming ↓, pending ↑ | null |
| 검수 (불량) | incoming ↓, pending ↑ → pending ↓, defect ↑ | null |
| 적치 완료 (정상) | pending@null ↓, available@실위치 ↑ | null → 실위치 |
| 적치 완료 (불량) | defect@null ↓, defect@불량존 ↑ | null → 불량존 |

---

## 2. 반품 입고

```
[출고지시서 선택]  →  [반품 입고지시서 생성]  →  이후 일반 입고와 동일
```

### 재고 변동

일반 입고와 **100% 동일한 흐름**.

### 추적 정보

| 필드 | 값 |
|------|-----|
| originType | `"return"` |
| originId | 출고지시서 UUID |
| returnFrom | 출고처명 (예: "강남지점") |

---

## 3. 일반 출고

```
[수주서]  →  [출고지시서]  →  [승인]  →  [피킹]  →  [출고확정]
```

### 재고 변동

| 단계 | 변화 | 위치 |
|------|------|------|
| 승인 | available ↓, reserved ↑ | 실위치 (분산) |
| 승인 (ATP 부분예약) | available에서 가능한 만큼만 reserve. 나머지는 적치 완료 시 autoReserve | 실위치 |
| 피킹 | 재고 변동 없음 (물리적 이동만) | - |
| 출고 확정 | reserved ↓ (실물 출고) | 실위치 |

### ATP (Available To Promise)

```
ATP = available + incoming + pending
→ ATP >= 출고 수량이면 승인 허용
→ 실제 reserve는 available에서 가능한 만큼만
→ 나머지는 입고 완료 시 자동 예약 (autoReserveUnfilledOrders)
```

## 4. 기타 입출고

```
[기타입출고 생성 (draft)]  →  [품목 추가]  →  [완료]  →  재고 반영
```

### IoType별 재고 변동

#### 입고 방향

| IoType | 설명 | 재고 변화 |
|--------|------|----------|
| `sample_in` | 샘플 입고 | available@위치 ↑ |
| `adjust_in` | 재고 조정 입고 | available@위치 ↑ |
| `etc_in` | 기타 입고 | available@위치 ↑ |
| `dispose_in` | 폐기 입고 (이동 기록) | 재고 변동 없음 |

#### 출고 방향

| IoType | 설명 | 재고 변화 |
|--------|------|----------|
| `sample_out` | 샘플 출고 | available@위치 ↓ |
| `adjust_out` | 재고 조정 출고 | available@위치 ↓ |
| `etc_out` | 기타 출고 | available@위치 ↓ |
| `dispose_out` | 폐기 출고 | defect@위치 ↓ |

## 5. 불량품 생명주기

```
입고 검수에서 불량 판정
        │
  defect@null ↑
        │
  불량 적치 (격리존 배정)
        │
  defect@null ↓
  defect@불량존위치 ↑
        │
  ┌─────┼─────┐
  │     │     │
폐기  수리   반송
  │     │     │
dispose adjust  이동
_out    _in   지시서
  │     │     │
defect↓ avail↑ 위치이동
```

| 이후 처리 | 방법 | 재고 변화 |
|----------|------|----------|
| 폐기 결정 | 기타입출고 `dispose_out` | defect@위치 ↓ |
| 수리 완료 | 기타입출고 `adjust_in` | available@위치 ↑ |
| 협력사 반송 | 이동 지시서 | 위치 간 이동 |

## 6. 부분 입고

```
지시수량 100개

[시나리오 A — 추가 입고로 완료]
1차 입고: 80개 정상, 5개 불량 → remainingQty: 15, status: shortage
2차 입고: 15개 정상           → remainingQty: 0,  status: completed
→ 적치 → 재고 반영 → 완료

[시나리오 B — 남은 수량 포기]
1차 입고: 80개 정상, 5개 불량 → remainingQty: 15, status: shortage
→ POST /close-shortage → shortage 강제 completed → 마감

[시나리오 C — 전량 입고]
1차 입고: 95개 정상, 5개 불량 → remainingQty: 0, status: completed
→ 기존과 동일
```

## 7. Inventory 테이블 수량 필드

```
┌───────────────────────────────────────────────────────┐
│                    Inventory Row                       │
│                                                        │
│  incomingQty  : 입고예정 (승인 시 ↑, 검수 시 ↓)        │
│  pendingQty   : 검수중   (검수 시 ↑, 적치 완료 시 ↓)    │
│  availableQty : 가용재고 (적치 완료 ↑, 출고 예약 ↓)     │
│  reservedQty  : 예약재고 (출고 승인 ↑, 출고 확정 ↓)     │
│  defectQty    : 불량재고 (검수 불량 ↑, 폐기 ↓)         │
│  ───────────────────────────────────────              │
│  totalQty     : 위 5개 합계 (자동 계산)                 │
│                                                        │
│  locationId   : null = 위치 미정 임시 행                │
│                 UUID = 확정 위치                        │
└───────────────────────────────────────────────────────┘
```

## 8. 전체 이벤트 — 재고 변동 요약

| 이벤트 | 변화 | 위치 |
|--------|------|------|
| 입고 승인 | incoming ↑ | null |
| 입고 검수 (정상) | incoming ↓, pending ↑ | null |
| 입고 검수 (불량) | incoming ↓, defect ↑ | null |
| 적치 완료 (정상) | pending@null ↓, available@실위치 ↑ | null → 실위치 |
| 적치 완료 (불량) | defect@null ↓, defect@불량존 ↑ | null → 불량존 |
| 출고 승인 | available ↓, reserved ↑ | 실위치 (분산) |
| 출고 확정 | reserved ↓ | 실위치 |
| 샘플/조정/기타 입고 | available ↑ | 지정 위치 |
| 샘플/조정/기타 출고 | available ↓ | 지정 위치 |
| 폐기 출고 | defect ↓ | 지정 위치 |
| 반품 입고 | 일반 입고와 동일 | 동일 |
